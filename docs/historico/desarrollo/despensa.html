Implementación completa del FE mock de la vista /despensa. En Sprint 4 la pantalla es totalmente funcional en memoria: los ingredientes persisten mientras la sesión del navegador está abierta pero no se comunica con el backend. La integración real con la API se realizará en Fase 5 (Sprint 5+).

La vista permite al usuario ver su despensa, añadir nuevos ingredientes con autocompletado, editar cantidad/unidad de los existentes y eliminarlos con animación de salida.

🏗️

Arquitectura de capas

El flujo sigue la regla del proyecto: Componente → Store. No hay servicios HTTP en Sprint 4. La página despensa/page.tsx es un Server Component que solo decide el layout; toda la lógica vive en el Client Component ContenidoDespensa.

Page (SC) app/(main)/despensa/page.tsx — layout mobile / desktop con SidebarNavPc
Orquestador (CC) ContenidoDespensa — consume store, gestiona sheetAbierto e itemEditando
Store useDespensaStore (Zustand) — ingredientes[], añadir, editar, eliminar
Datos mock datosDespensa.ts — 12 ítems iniciales, mapa de emojis, helper
Tipos despensa.types.ts — interfaz ItemDespensa
Reutilizados useAutocompletadoIngredientes (recetas) · UNIDADES_INGREDIENTE (recetas)
Reutilización deliberada: El hook useAutocompletadoIngredientes ya combina la base de datos local de ingredientes, el store de ingredientes custom y el fallback Edamam. No se duplicó nada — la despensa lo importa directamente desde features/recetas/hooks.

¿De dónde vienen los emojis?

Los emojis son completamente estáticos: no hay API, no hay LLM, no hay librería externa. Se mantiene un Record<string, string> de ~50 entradas con nombres de ingredientes comunes como clave y su emoji Unicode como valor. El helper getEmojiIngrediente normaliza a minúsculas y devuelve '🥘' si no hay coincidencia. 

export function getEmojiIngrediente(nombre: string): string {
  return EMOJIS_INGREDIENTES[nombre.toLowerCase()] ?? '🥘'
}

Esta estrategia es intencionada para Sprint 4 (mock). Posibles mejoras en Sprint 5+:

  • El backend puede devolver el campo emoji desde la BD junto al resto del ítem.
  • Usar una librería como node-emoji para mapeo automático por nombre.
  • Eliminar la dependencia del frontend cuando el campo venga del BE.

Store Zustand — despensaStore

Store Zustand sin persistencia (sin persist middleware). En Sprint 4 la intención es que el estado se resetee al recargar la página — es un mock. Sprint 5 añadirá la integración real con la API.

Shape del estado

interface DespensaState {
  ingredientes: ItemDespensa[]
  añadir:  (item: Omit<ItemDespensa, 'id'>) => void
  editar:  (id: string, cambios: Partial<Omit<ItemDespensa, 'id'>>) => void
  eliminar:(id: string) => void
}

Generación de IDs

Al añadir un ítem se genera un ID único combinando timestamp + 4 chars random en base 36. No se usa crypto.randomUUID() para evitar dependencia de contexto seguro en tests. 

id: `${Date.now()}-${Math.random().toString(36).slice(2, 6)}`

Decisiones de diseño

DecisiónAlternativa descartadaPor qué
Zustand sin persist LocalStorage / persist middleware Sprint 4 es mock puro. Persistencia vendría del BE en Fase 5, no del localStorage
Estado inicializado con mock Estado vacío Permite revisar la UI completa sin tener que añadir ingredientes manualmente
Store en stores/despensaStore.ts Dentro de features/despensa/ Convención del proyecto: stores globales van en src/stores/

Componentes

contenidoDespensa.tsx
Client Component Orquestador principal. Consume useDespensaStore y gestiona los dos estados locales: sheetAbierto (boolean) e itemEditando (ItemDespensa | null). Es el único componente que conoce el store; el resto solo recibe props. Renderiza todos los demás subcomponentes.
headerDespensa.tsx Header editorial al estilo "The Digital Gourmet": "¡Bienvenido a tu Despensa!". La palabra "Despensa" va en font-black italic text-brand. Muestra el total de ingredientes con la construcción "N ingrediente/s guardado/s".
barraAnadirIngrediente.tsx Pill CTA siempre visible bajo el header. Texto "¿Quieres añadir algún alimento?" + botón circular + en color brand. Toda la fila es clickable (abre el Sheet). No tiene estado propio — llama a onAbrir().
estadoVacioDespensa.tsx Estado vacío: icono ShoppingBasket de Lucide, texto "Tu despensa está vacía" y botón brand "Añadir primer ingrediente". Se muestra cuando ingredientes.length === 0.
listaIngredientes.tsx Wrapper de animaciones. Usa AnimatePresence initial={false} de Framer Motion para que las tarjetas salientes tengan animación de exit sin que las entradas se animen en la carga inicial. Renderiza una TarjetaIngrediente por ítem.
tarjetaIngrediente.tsx motion.div con layout (reflow suave al eliminar vecinos) + exit={{ opacity: 0, x: 32 }} (desliza a la derecha al eliminar). Muestra: emoji en círculo bg-[var(--warm-bg-accent)], nombre en negrita, cantidad + unidad, botón lápiz (editar) y botón papelera (eliminar).
sheetAnadirIngrediente.tsx shadcn Sheet side="bottom" con rounded-t-3xl. Contiene: (1) input de búsqueda con useAutocompletadoIngredientes y dropdown de hasta 5 sugerencias, (2) chips de sugerencias rápidas cuando el input está vacío [Tomate, Cebolla, Ajo, Zanahoria, Patata, Huevos], (3) campo de cantidad + select de unidad reutilizando UNIDADES_INGREDIENTE de recetas. El onBlur cierra el dropdown con un setTimeout(150ms) para que el tap en una sugerencia se registre antes.

Detección de duplicados: al pulsar "Añadir", handleAnadir() lee useDespensaStore(s => s.ingredientes) y busca por nombre case-insensitive. Si el ingrediente ya existe, en lugar de añadirlo abre un shadcn Dialog con el estado nombreDuplicado. El Dialog muestra icono AlertCircle y el mensaje "«nombre» ya está en tu despensa. Si quieres modificarlo, edítalo o elimínalo directamente desde la lista." El botón "Entendido" cierra el Dialog. El store permanece sin cambios.
dialogEditarIngrediente.tsx shadcn Dialog (modal centrado, no Sheet) para editar un ítem ya existente. Pre-rellena nombre, cantidad y unidad desde el prop item. Muestra el emoji del ítem en el título del dialog. No permite cambiar el nombre — solo cantidad y unidad.
Sheet vs Dialog: se usa Sheet (bottom slide-up) para "añadir" porque es un flujo con más contenido y se siente más como una tarea. Se usa Dialog (modal centrado) para "editar" porque es una acción rápida sobre un ítem que el usuario ya conoce.

Flujos de interacción

Añadir ingrediente

1
Usuario pulsa la barra CTA o el + circular ContenidoDespensa → setSheetAbierto(true)
2
SheetAnadirIngrediente se abre desde abajo shadcn Sheet con side="bottom" y rounded-t-3xl
3
Usuario escribe el nombre — aparecen sugerencias del autocompletado useAutocompletadoIngredientes(nombre) → BD local + custom + Edamam fallback
4
Usuario selecciona una sugerencia (o escribe libre) y rellena cantidad + unidad
5
Pulsa "Añadir" — se llama onAnadir(item) handleAnadir() → getEmojiIngrediente(nombre) → store.añadir(item)
6
Sheet se cierra, estado se resetea, nueva tarjeta aparece en la lista

Ingrediente duplicado

1
Usuario rellena nombre + cantidad y pulsa "Añadir" handleAnadir() — nombre ≥2 chars, cantidad > 0
2
El componente compara el nombre contra el store (case-insensitive) ingredientes.some(ing => ing.nombre.toLowerCase() === nombreTrimmed.toLowerCase())
3
El nombre ya existe → setNombreDuplicado(nombreTrimmed) El Sheet permanece abierto. No se modifica el store.
4
Dialog superpuesto (shadcn Dialog) aparece con icono AlertCircle "«{nombre}» ya está en tu despensa. Si quieres modificarlo, edítalo o elimínalo directamente desde la lista."
5
Usuario pulsa "Entendido" → setNombreDuplicado(null) — Dialog se cierra, Sheet sigue abierto

Editar ingrediente

1
Usuario pulsa el icono lápiz en TarjetaIngrediente onEditar(item) → ContenidoDespensa → setItemEditando(item)
2
DialogEditarIngrediente aparece pre-rellenado con los datos del ítem
3
Usuario modifica cantidad y/o unidad → pulsa "Guardar" onGuardar(cambios) → store.editar(id, cambios) → setItemEditando(null)

Eliminar ingrediente

1
Usuario pulsa icono papelera en TarjetaIngrediente onEliminar(item.id) → store.eliminar(id)
2
Framer Motion anima la salida: opacity: 0, x: 32 en 180ms AnimatePresence en ListaIngredientes → exit en motion.div
3
La propiedad layout hace que las tarjetas restantes se reposicionen suavemente
4
Si era el último ítem, aparece EstadoVacioDespensa

Diseño — referencia Stitch

El diseño sigue el sistema editorial "The Digital Gourmet" definido en docs/diseno/stitch/. Las reglas más relevantes aplicadas en la despensa:

Regla StitchAplicación en /despensa
No-Line Rule Las secciones se separan por diferencia de fondo (bg-background → var(--warm-bg)), nunca con bordes de 1px entre secciones
Header editorial "¡Bienvenido a tu Despensa!" — palabra clave en font-black italic text-brand, mismo patrón que ColecciónHeader y Mis Recetas
CTA primario Botón bg-brand text-brand-foreground redondeado (rounded-2xl), tamaño full-width en contexto Sheet/Dialog
Emoji avatar Círculo bg-[var(--warm-bg-accent)] en tarjeta, sin imagen real — warm palette del sistema de diseño
Input fields Fondo var(--warm-bg), rounded-2xl, sin borde visible — tonal layering en lugar de líneas
Chips de sugerencia bg-[var(--warm-bg)] en reposo, bg-[var(--warm-bg-accent)] en hover — temperatura cálida coherente

Integración BE — Fase 5

Todo lo que hay que cambiar cuando el backend de despensa esté disponible. El FE mock está estructurado para que la migración sea mínima.

FicheroCambio necesario
stores/despensaStore.ts Reemplazar estado inicial con llamada a despensaService.getMiDespensa(). Convertir acciones a llamadas HTTP + actualización optimista.
services/despensaService.ts Crear este fichero con getMiDespensa(), añadirItem(), editarItem(), eliminarItem() usando apiClient.
features/despensa/hooks/ Opcionalmente crear useMiDespensa.ts con TanStack Query (igual que useMisRecetas y useRecetasGuardadas).
data/datosDespensa.ts El mock de 12 ítems puede quedar como fallback de desarrollo. getEmojiIngrediente puede mantenerse o eliminarse si el BE devuelve el campo emoji.
types/despensa.types.ts Posiblemente añadir updatedAt, userId u otros campos que devuelva la API.
Actualización optimista: dado que eliminar y editar tienen animaciones visibles, la UX esperada en Fase 5 es actualización optimista (el estado local cambia inmediatamente) con rollback en caso de error de red — mismo patrón que el bookmark de recetas (COL-005).
