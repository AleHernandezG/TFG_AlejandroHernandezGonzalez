📸 Foto Automática Pexels — FOTO-001 + FOTO-002

Foto automática al publicar receta sin imagen · Créditos Pexels obligatorios · Sprint 4

📋

Resumen

Sprint 4

Cuando un usuario publica una receta sin subir foto, el backend busca automáticamente una imagen relacionada en Pexels API (gratuita, 200 req/h). Si la encuentra, la guarda como imagenUrl junto a los créditos del fotógrafo.

En la vista de detalle de receta, si la foto proviene de Pexels se muestra la atribución obligatoria: "Foto por [nombre] en Pexels" con los enlaces requeridos por la licencia Pexels.

La licencia Pexels exige mostrar el nombre del fotógrafo y el enlace a la foto. FOTO-002 cubre este requisito legal.
🔄

Flujo completo al publicar sin foto

1
Usuario rellena el formulario de crear receta sin subir imagen y pulsa "Publicar".
2
FE envía POST /api/recetas con el body sin imagenBase64.
3
El controller valida con Zod y llama a recetasService.crear().
4
El service llama a recetaRepository.crear().
5
El repository detecta !datos.imagenBase64 → llama a imagenService.buscarFotoPexels(datos.titulo).
6
Pexels devuelve la foto más relevante para el título. Si falla o no hay resultados, imagenUrl queda vacío y fotoFuente = 'usuario'.
7
MongoDB guarda: imagenUrl (URL Pexels), fotoFuente: 'pexels', fotoCredito: { fotografo, urlFoto, urlPerfil }.
8
Al visitar la receta, SSR llama a GET /api/recetas/:id que devuelve los campos de crédito.
9
FE: heroReceta.tsx muestra la imagen y, si fotoFuente === 'pexels', renderiza la atribución bajo la imagen.

Pexels API — detalles técnicos

Endpoint: GET https://api.pexels.com/v1/search

Parámetros:

query        → título de la receta (ej: "Pasta Carbonara")
per_page     → 1 (solo necesitamos la primera foto)
orientation  → landscape (fotos apaisadas, mejor para el hero)

Cabecera: Authorization: PEXELS_API_KEY

Respuesta relevante:

{
  "photos": [{
    "src": {
      "large2x": "https://images.pexels.com/photos/.../large2x.jpeg",
      "large":   "https://images.pexels.com/photos/.../large.jpeg"
    },
    "photographer":     "John Doe",
    "url":              "https://www.pexels.com/photo/...",
    "photographer_url": "https://www.pexels.com/@johndoe"
  }]
}

Tier gratuito: 200 req/hora · sin límite mensual · uso comercial permitido.

Variable de entorno: PEXELS_API_KEY en backend/.env y en Render (Fase 6).

Modelo de datos MongoDB — campos nuevos

// Receta (campos añadidos)
{
  fotoFuente: "usuario" | "pexels",   // default: "usuario"
  fotoCredito: {                       // null si fotoFuente === "usuario"
    fotografo: string,
    urlFoto:   string,   // enlace a la foto en Pexels
    urlPerfil: string    // enlace al perfil del fotógrafo
  } | null
}

Los campos son opcionales en Mongoose para compatibilidad con recetas existentes (sin foto Pexels). Si fotoFuente no existe en el documento se interpreta como 'usuario'.

⚖️

Atribución Pexels — FOTO-002 (obligatoria por licencia)

La licencia Pexels exige mostrar el nombre del fotógrafo y enlazar tanto a la foto como al perfil. Se muestra debajo del hero con estilo discreto:

// heroReceta.tsx — solo se renderiza cuando fotoFuente === 'pexels'
<p className="px-5 pt-1.5 text-[11px] text-muted-foreground">
  Foto por{' '}
  <a href={fotoCredito.urlPerfil} target="_blank" rel="noopener noreferrer"
     className="underline underline-offset-2 hover:text-foreground">
    {fotoCredito.fotografo}
  </a>{' '}en{' '}
  <a href={fotoCredito.urlFoto} target="_blank" rel="noopener noreferrer"
     className="underline underline-offset-2 hover:text-foreground">
    Pexels
  </a>
</p>
Se usa rel="noopener noreferrer" en todos los enlaces externos (seguridad). El texto usa text-muted-foreground para no interferir visualmente con el contenido de la receta.
🔁

Compatibilidad con recetas existentes

Las recetas ya publicadas en MongoDB no tienen los campos fotoFuente ni fotoCredito. El repositorio devuelve fotoFuente: 'usuario' (fallback con ??) y fotoCredito: null, por lo que el componente heroReceta.tsx nunca renderiza la atribución para estas recetas.

No es necesaria ninguna migración de datos.
