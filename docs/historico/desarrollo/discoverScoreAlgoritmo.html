Problema original

El tab "Recientes" en /discover ordenaba por fecha de publicación pura (sort: 'reciente'). Una receta publicada hace 5 minutos con 0 likes aparecía antes que una publicada hace 2 días con 200 likes y 40 comentarios.

El tab "Mejor valorados" ordenaba por número de likes en bruto, sin decaimiento temporal. Una receta de hace un año con 500 likes bloqueaba permanentemente el top, independientemente de la actividad reciente.

El resultado: el feed no premiaba contenido de calidad reciente ni tenía en cuenta la relevancia personal del usuario.

📐

Fórmula de scoring

score = (likes × 2 + comentarios × 3) × decay + followBoost + prefBoost
calculado en memoria para cada documento antes del sort

Variables

VariableCálculoRazón
popularidad likes×2 + comentarios×3 Comentar requiere más intención que un like. Peso mayor en comentarios.
decay 1 / (1 + √diasAntiguo) Curva suave con raíz cuadrada. Penaliza el tiempo sin colapsar recetas de días anteriores.
followBoost +1.5 si sigues al autor Bonus pequeño de cercanía social. No domina el score, pero desempata.
prefBoost +0.5 × categorías coincidentes Cada categoría de la receta que coincida con las preferencias del usuario suma 0.5.
📉

Curva de decaimiento temporal

La función 1 / (1 + √t) produce una curva suave: cae rápido los primeros días (cuando el contenido es más relevante) y se estabiliza en valores bajos para contenido antiguo.

Una receta con 100 likes publicada hoy (decay=1.0) tiene score 200. La misma receta publicada hace 30 días tiene score 30. Una receta de hace una semana con 500 likes tiene score 135 — supera a la nueva con 100 likes.

Implementación

Flujo de datos

GET /api/recetas?sort=score → recetasController → recetasService.obtenerFeed() → recetaRepository.findAll() → rama sort==='score'

Rama score en findAll()

if (sort === 'score') {
  const [todos, preferencias] = await Promise.all([
    Receta.find(query).populate("autorId", "nombre foto").lean().exec(),
    usuarioId ? obtenerPreferenciasUsuario(usuarioId) : Promise.resolve([]),
  ]);

  const ahora = new Date();
  const segSet = seguidosSet ?? new Set<string>();

  todos.sort((a, b) => {
    const sa = calcularScoreFeed(a, ahora, segSet, preferencias);
    const sb = calcularScoreFeed(b, ahora, segSet, preferencias);
    return sb - sa;
  });

  total = todos.length;
  docs = todos.slice(skip, skip + limite);
}

Función calcularScoreFeed()

function calcularScoreFeed(
  doc: Record<string, unknown>,
  ahora: Date,
  seguidosSet: Set<string>,
  preferencias: string[],
): number {
  const likes = (doc.likes as unknown[]).length;
  const comentarios = (doc.listaComentarios as unknown[]).length;
  const fecha = doc.fechaPublicacion as Date;
  const diasAntiguo = (ahora.getTime() - fecha.getTime()) / (1000 * 60 * 60 * 24);

  const popularidad = likes * 2 + comentarios * 3;
  const decay = 1 / (1 + Math.sqrt(Math.max(0, diasAntiguo)));

  const autor = doc.autorId as { _id: { toString(): string } };
  const followBoost = seguidosSet.has(autor?._id?.toString() ?? "") ? 1.5 : 0;

  const categorias = (doc.categorias as string[]) ?? [];
  const prefBoost = categorias.filter((c) => preferencias.includes(c)).length * 0.5;

  return popularidad * decay + followBoost + prefBoost;
}

Helper obtenerPreferenciasUsuario()

async function obtenerPreferenciasUsuario(usuarioId: string): Promise<string[]> {
  const usuario = await Usuario.findById(usuarioId)
    .select("preferencias")
    .lean()
    .exec();
  return (usuario?.preferencias as string[] | undefined) ?? [];
}

Decisiones de diseño

Sin cambios de schema

Las "guardadas" de una receta viven en usuario.recetasGuardadas, no en el documento de receta. Añadir un contador de guardados requeriría una migración de schema. La decisión fue usar solo likes y listaComentarios, ambos ya presentes en el documento.

Sort in-memory

El mismo patrón que la rama existente sort === 'likes'. Carga todos los documentos que pasan los filtros, los puntúa y ordena en Node, y luego pagina con slice(). Válido a escala de TFG. Para producción real se optaría por un campo precalculado en MongoDB con índice.

Tab "Recientes" → score

El algoritmo ya premia la recencia via decay, así que "Recientes" no pierde su semántica: el contenido de hoy sigue apareciendo arriba si tiene algo de actividad. La diferencia es que una receta con 0 interacciones publicada hace 10 minutos ya no bloquea el top solo por ser nueva.

Tab "Mejor valorados" sin cambios

Sigue usando sort: 'likes' puro — ranking histórico de likes sin decaimiento. Tiene sentido mantenerlo como referencia de "lo más popular de siempre".

Promise.all() para reducir latencia

La query de recetas y obtenerPreferenciasUsuario() se ejecutan en paralelo. La seguidosSet ya estaba disponible en ese punto del flujo (calculada antes del bloque de sort), sin coste extra.
