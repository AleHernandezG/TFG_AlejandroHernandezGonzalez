¿Qué es la despensa?

La despensa es la lista personal de ingredientes que el usuario tiene en casa. Cada usuario puede añadir, editar y eliminar ingredientes. Los ingredientes se guardan directamente dentro del documento del usuario en MongoDB (subdocumento embebido).

¿Para qué sirve?

  • Ver qué ingredientes tienes disponibles en casa.
  • Añadir ingredientes manualmente (con nombre, cantidad, unidad y emoji).
  • Importar los ingredientes de una receta directamente a tu despensa.
  • Editar o eliminar cualquier ingrediente.

Decisión de diseño: subdocumento embebido

Los ítems de la despensa se guardan como un array despensa: IItemDespensa[] dentro del documento Usuario en MongoDB. No hay una colección separada. Esta decisión simplifica las consultas (un solo findById trae todo) y es adecuada para listas personales de tamaño moderado.

Flujo de datos

Leer la despensa (GET)

ContenidoDespensa → useMiDespensa (useQuery) → despensaService.obtener() → GET /api/despensa → Usuario.findById().select('despensa')

Añadir ingrediente (POST)

SheetAnadirIngrediente → useAñadirItem (optimistic) → despensaService.añadir() → POST /api/despensa → $push despensa

Editar ingrediente (PUT)

DialogEditarIngrediente → useEditarItem (optimistic) → despensaService.editar() → PUT /api/despensa/:id → $set despensa.$.campo

Eliminar ingrediente (DELETE)

TarjetaIngrediente → useEliminarItem (optimistic) → despensaService.eliminar() → DELETE /api/despensa/:id → $pull despensa { _id }

Optimistic updates

Las tres mutations (añadir, editar, eliminar) usan el patrón optimistic update + rollback:

  • onMutate: cancela queries en vuelo, guarda el estado anterior, actualiza el cache TanStack Query inmediatamente.
  • onError: restaura el estado anterior si el backend falla.
  • onSuccess: sincroniza el cache con el array real devuelto por el backend.

API endpoints — /api/despensa

MétodoRutaAuthBodyRespuesta

Sprint 6 · C4 — DESP-TICKET-001: Escanear ticket de compra

El usuario fotografía un ticket de supermercado. Gemini Vision extrae los ingredientes alimentarios y muestra una lista de confirmación. Al confirmar, los ingredientes se añaden a la despensa de forma consolidada.

⚠️ Requiere GEMINI_API_KEY en backend/.env. Sin clave: error 503 manejado con mensaje visible.

Mejoras de Limpieza y Normalización (FE)

Los ingredientes extraídos por Gemini pasan por un proceso intermedio en el cliente (normalizadorIngredientes.ts) antes de previsualizarse:

  • Filtro de Marcas: Limpieza de marcas españolas comerciales (Hacendado, La Lechera, Orlando, Solís, Pascual, etc.) y eliminación de textos adicionales (ej: entre paréntesis).
  • Homologación de nombres: Se busca similitud exacta o a través de alias en la lista local (INGREDIENTES_COMUNES). Adicionalmente, cuenta con un algoritmo de matching por tokens significativos (descomponiendo el texto en palabras clave sin conectores como *para*, *de*, *con*), permitiendo asociar de forma sumamente precisa productos que omiten conectores como `"nata montar asturian"` con `"Nata para montar"` o `"queso untar"` con `"Queso crema"`.
  • Agrupación y Fusión: Conversión de unidades de escala (kg → g, l → ml), agrupación y suma de cantidades de ítems idénticos para mostrarlos consolidados.
  • Tratamiento de Unidades y Plurales: Si el ingrediente carece de unidad o es vacío en el ticket (ej. "Pan de molde Dia"), se asigna por defecto "unidad". Si contiene una unidad en plural (ej. "sobres", "latas", "bolsas"), se mapea automáticamente a su formato singular estándar ("sobre", "lata", "bolsa") para encajar con los dropdowns del formulario visual. Adicionalmente, se aplica una lista blanca de unidades válidas, forzando un fallback a "unidad" si la IA extrae palabras erróneas del ticket como unidad de medida (ej. *"Azúcar 1 dia"*, donde la marca *"dia"* se interpretaba incorrectamente como unidad).

Inserción por Lotes (Batch Add)

Para solucionar fallos de persistencia (F5) y pérdida de ingredientes (conflictos de concurrencia en MongoDB al guardar concurrentemente), la inserción se realiza en una sola petición agrupada de red:

  • Backend Multiuso: El endpoint POST /api/despensa acepta tanto un objeto individual como un array de objetos.
  • Atomicidad en BD: Se utiliza el operador $each de MongoDB ({ $push: { despensa: { $each: items } } }) para guardar todo el lote en una sola operación de escritura.
  • Actualización del Caché: La mutación de TanStack Query (useAñadirItem) procesa el lote de forma optimista con un rollback seguro en caso de error.
