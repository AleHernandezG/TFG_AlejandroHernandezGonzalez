1. Visión general

La vista Home es el punto de entrada principal de la aplicación tras el login. Implementa el feed personal de recetas (TFG-20) con datos mock hasta la Fase 5, cuando se conectará el backend real. El diseño sigue los principios editoriales del DESIGN.md de Stitch: paleta cálida, glassmorphism en elementos flotantes, imágenes con rounded-2xl y separación por tono en lugar de bordes duros.

A partir del 2026-04-01, la vista es completamente responsive: en dispositivos lg+ (≥ 1024px) se renderiza un layout editorial de tres columnas (sidebar nav · feed bento · sidebar tendencias), mientras que en mobile (< lg) se mantiene el layout original de columna única con scroll vertical.

3. Layout responsive — Mobile vs Desktop

Mobile (< lg · < 1024px)

Columna única con scroll vertical. Ningún elemento es sticky: tanto el header como el buscador desaparecen al hacer scroll (decisión de diseño [UI-014]). Solo el NavBarInferior permanece anclado en la parte inferior.

CapaComponentez-indexPosición
1ª HeaderHome natural flujo normal, desaparece al scroll
2ª BuscadorFiltros (dentro de FeedHome) natural flujo normal, desaparece al scroll
3ª FeedHome (lista de cards) natural scrollable
4ª NavBarInferior z-50 fixed bottom-0 (ya existía)

Desktop (lg+ · ≥ 1024px)

Layout editorial de tres columnas fijas. El NavBarInferior se oculta automáticamente (lg:hidden ya incluido en su implementación). La navegación se realiza a través del SidebarNavPc.

CapaComponentez-indexDimensionesPosición
Header HeaderHomePc z-50 100% ancho · h-20 fixed top-0 left-0 right-0
Sidebar izq. SidebarNavPc z-40 w-64 · 100% alto fixed left-0 top-0 · pt-24
Contenido central FeedHomePc (dentro de main) natural fluido entre sidebars pl-64 pr-80 pt-28 para compensar fixed elements
Sidebar der. SidebarTendencias z-40 w-80 · 100% alto fixed right-0 top-0 · pt-28
Glassmorphism en desktop: El HeaderHomePc usa bg-background/80 backdrop-blur-md, igual que el header mobile original. Los sidebars usan bg-background sólido (sin blur) para no competir visualmente con el feed central.
Rendimiento de layout: Los tres elementos fijos del desktop (HeaderHomePc, SidebarNavPc, SidebarTendencias) son promovidos a su propia capa de composición por el navegador gracias a position: fixed, evitando repaints durante el scroll del feed central.

Función de tiempo relativo

function tiempoRelativo(fechaISO: string): string {
  const diffMs  = Date.now() - new Date(fechaISO).getTime()
  const diffMin = Math.floor(diffMs / 60_000)
  if (diffMin < 60) return `Hace ${diffMin}m`
  const diffH = Math.floor(diffMin / 60)
  if (diffH < 24) return `Hace ${diffH}h`
  return `Hace ${Math.floor(diffH / 24)}d`
}

const postsFiltrados = POSTS_MOCK.filter((post) => {

10. page.tsx — Server Component

Fichero: app/(main)/home/page.tsx

PaginaHome es un Server Component puro. No contiene ningún hook, estado ni manejador de eventos. Actúa como selector responsive: renderiza el layout mobile o el layout desktop dependiendo del breakpoint lg mediante clases Tailwind. 

import { FeedHome, HeaderHome, LayoutHomePc } from '@/features/recetas/components'

export const metadata = {
  title: 'Inicio — Cookr',
  description: 'Tu feed personalizado de recetas. Descubre, guarda y cocina.',
}

export default function PaginaHome() {
  return (
    <>
      {/* ── Mobile layout (visible únicamente si viewport < lg) ── */}
      <div className="min-h-screen bg-background lg:hidden">
        <HeaderHome />
        <FeedHome />
      </div>

      {/* ── Desktop layout (visible únicamente si viewport ≥ lg) ── */}
      <div className="hidden lg:block">
        <LayoutHomePc />
      </div>
    </>
  )
}
Por qué CSS y no JS: Usar hidden lg:block / lg:hidden en lugar de useWindowSize() garantiza que el HTML correcto se genera en el servidor y no hay flash de contenido incorrecto (FOUC) en el cliente. Ambos layouts están presentes en el DOM pero solo uno es visible en cada breakpoint.
