Opción 1 — Nodemailer + Gmail SMTP (recomendado)
Coste: 0€. Sin dominio. Envía a cualquier correo.

Usas una cuenta de Gmail como servidor de envío. No hay que cambiar nada del frontend ni de la lógica — solo email.ts usa nodemailer en lugar de Resend.

Setup:

En tu cuenta Gmail → Seguridad → Verificación en 2 pasos (activar si no lo está)
Seguridad → Contraseñas de aplicación → crear una para "Correo / Windows/Mac/Linux" → copia los 16 caracteres
En backend/.env: GMAIL_USER=tucuenta@gmail.com y GMAIL_APP_PASSWORD=xxxx xxxx xxxx xxxx
npm install nodemailer @types/nodemailer en backend
Límite: 500 emails/día por cuenta Gmail. Para un TFG es infinito en la práctica.

Opción 2 — Brevo (ex-Sendinblue)
Coste: 0€. Sin dominio. Envía a cualquier correo. 300 emails/día gratis.

Servicio profesional de email marketing con API similar a Resend. El free tier no requiere verificar dominio para envíos básicos.

Setup:

Crear cuenta en brevo.com
Settings → SMTP & API → crear API Key
npm install @getbrevo/brevo en backend
from puede ser cualquier correo que verifiques como remitente (te mandan un email de verificación al correo que pongas)

Opción 4 — Mailtrap (solo para dev, no llega al inbox real)
Coste: 0€. Intercepta todos los emails en una bandeja de pruebas online. No llega al correo real del usuario pero puedes ver el HTML exacto del email.

Útil si solo quieres comprobar que el email se genera correctamente sin preocuparte de que llegue.

Mi recomendación para el TFG
Nodemailer + Gmail. Es lo más simple, cero coste, cero configuración de plataformas externas, y envía a cualquier correo real. La única pega es que el remitente aparece como tu cuenta de Gmail en lugar de noreply@cookr.app, pero para un TFG es más que suficiente. En la Fase 6 de producción real se podría migrar a Resend con dominio verificado sin tocar nada del frontend.
