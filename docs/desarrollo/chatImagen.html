Contexto

El botón del clip (Paperclip) en barraInputChat.tsx era un elemento visual sin onClick, completamente inerte. El chat solo aceptaba texto.

Gemini Flash soporta entrada multimodal (texto + imagen) mediante inlineData. Implementar este flujo permite al usuario fotografiar un plato, una nevera con ingredientes o una receta escrita en papel y pedirle al asistente que la analice.

Frontend — barraInputChat.tsx

Se añade un input[type=file] oculto con ref, accionado desde el botón Paperclip. Al seleccionar un archivo se convierte a base64 con FileReader.readAsDataURL().

function handleFileChange(e: React.ChangeEvent<HTMLInputElement>) {
  const file = e.target.files?.[0]
  if (!file) return
  if (file.size > 4 * 1024 * 1024) return   // 4 MB límite cliente
  const reader = new FileReader()
  reader.onload = (ev) => setImagen(ev.target?.result as string)
  reader.readAsDataURL(file)
  e.target.value = ''   // permite re-seleccionar el mismo archivo
}

Preview thumbnail: cuando hay imagen seleccionada se muestra un img de 64×64 px encima del input, con botón X (XIcon) superpuesto para quitarla. El clip se colorea con text-brand cuando hay imagen activa.

Placeholder dinámico: cuando hay imagen el textarea muestra "Pregunta algo sobre la imagen…" en lugar del placeholder por defecto.

Envío sin texto: el botón de enviar también se activa cuando hay imagen aunque el textarea esté vacío. En ese caso se manda solo la imagen y el backend añade un prompt por defecto.

const puedeEnviar = (valor.trim().length > 0 || imagen !== null) && !deshabilitado

Prop actualizada:

onEnviar: (texto: string, imagen?: string) => void

Backend — chat.routes.ts + chatService.ts

chat.routes.ts extrae imagenBase64 del body como campo opcional y lo valida antes de pasarlo al service:

if (imagenBase64 !== undefined) {
  if (typeof imagenBase64 !== "string" || !imagenBase64.startsWith("data:image/")) {
    res.status(400).json({ error: "imagenBase64 no válida" })
    return
  }
  if (imagenBase64.length > 7_000_000) {
    res.status(400).json({ error: "La imagen no puede superar 5 MB" })
    return
  }
}

chatService.ts actualiza la firma de responderChat:

  mensajes: MensajeChat[],

Gemini Vision — cómo se envía la imagen

Cuando llega imagenBase64, el último mensaje al modelo se construye con dos partes en lugar de solo texto:

if (imagenBase64) {
  const partes = imagenBase64.split(",")
  const mimeType = partes[0].match(/:(.*?);/)?.[1] ?? "image/jpeg"
  const data = partes[1] ?? partes[0]
  result = await chat.sendMessage([
    { inlineData: { mimeType, data } },
    { text: ultimo.texto || "¿Qué ves en esta imagen? Ayúdame en el contexto culinario." },
  ])
}

El mimeType se extrae del propio prefijo base64 (data:image/jpeg;base64,…), por lo que funciona con JPEG, PNG, WebP y cualquier formato que el navegador incluya en readAsDataURL().

Si el usuario no escribe texto pero adjunta una imagen, el prompt por defecto es "¿Qué ves en esta imagen? Ayúdame en el contexto culinario." para que Gemini siempre tenga contexto gastronómico.

El historial de mensajes anteriores (history) se mantiene igual que en el chat de solo texto; la imagen viaja únicamente en el último turno.

Límites y seguridad

Servidor (BE)Formato obligatorioDebe empezar con data:image/

La validación en cliente (4 MB) actúa como primera barrera UX — evita que el usuario espere a un rechazo del servidor. La validación de servidor es la barrera de seguridad real.

localStorage — por qué las imágenes no se guardan en historial

Una imagen base64 de 2 MB codificada pesa ~2.7 MB como string. El límite de localStorage en la mayoría de navegadores es de 5–10 MB por origen. Guardar imágenes en el historial agotaría ese espacio con dos o tres conversaciones.

La solución: al llamar a nuevaConversacion(), los mensajes se copian al historial sin el campo imagen:

mensajes: mensajes.map(({ imagen: _img, ...rest }) => rest)

La imagen es visible durante la sesión activa (vive en el estado en memoria de Zustand). Al restaurar una conversación del historial, los mensajes aparecen con el texto pero sin la imagen. Esto es un trade-off aceptable: la imagen cumplió su propósito en el intercambio original.
