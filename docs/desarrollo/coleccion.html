Sistema de diseño del Stitch — The Culinary Editorial

El DESIGN.md adjunto a ambos Stitches define la filosofía "Digital Gourmet Editorial": paleta warm ochre, regla No-Line (separación por color de fondo, no por bordes), sombras ambient (0px 12px 32px rgba muy sutil) y esquinas xl (1.5rem). Todo ello ya es nativo en el sistema Cookr — la traducción fue directa.

1
Usuario abre /coleccion La vista carga con la pestaña "Guardadas" activa por defecto
2
Header sticky muestra: título editorial + contador de recetas + segmented control pill "¡Mis recetas Guardadas!" · "4 recetas guardadas"
3
Si hay recetas → GridRecetasColeccion: cuadrícula 2 columnas, cards portrait 3:4 Guardadas: bookmark filled top-right · Mis Recetas: ··· top-right
4
Si no hay recetas → estado vacío específico por pestaña Guardadas: Bookmark icon + CTA "Explorar recetas" → /home · Mis Recetas: ChefHat + CTA "Crear primera receta" → /crear-receta
5
Usuario toca el segmented control → cambia de pestaña AnimatePresence fade suave (0.22s easeOut entrada, 0.15s easeIn salida). Título y contador se actualizan según la pestaña activa
6
Usuario toca una tarjeta → navega a /recetas/[id] El botón (bookmark o ···) dentro de la tarjeta hace e.preventDefault() + e.stopPropagation() para no navegar

Traducción Stitch → Sistema Cookr

El Stitch usa colores del Material Design 3 (tema warm ochre). Cada token se mapea a las variables CSS de globals.css o a las excepciones documentadas en rules.md §3. Cero colores hardcodeados.

STITCH COOKR
bg-primary (#855400) → bg-brand
text-on-primary (#ffffff) → text-brand-foreground
bg-surface-container-high (#e9e8e4) → bg-muted (track del toggle)
bg-surface-container-lowest (#ffffff) → bg-card (header, botón bookmark)
bg-background (#faf9f5) → bg-background
text-secondary (#5f5e5e) → text-muted-foreground
text-on-background (#1b1c1a) → text-foreground
shadow 0px 12px 32px rgba(27,28,26,0.06) → shadow-[0px_12px_32px_oklch(0.22_0.02_50_/_0.06)]
shadow header 0px 12px 32px rgba(...0.02) → shadow-[0px_12px_32px_oklch(0.22_0.02_50_/_0.02)]
bg-gradient-to-t from-black/80 via-black/20 → bg-gradient-to-t from-black/80 via-black/20 to-transparent (excepción permitida)
bg-surface-container-lowest/80 backdrop-blur-sm → bg-white/80 backdrop-blur-sm (excepción sobre foto)

rounded-xl (24px del Stitch) → rounded-xl (mismo valor en Tailwind del proyecto)

Regla No-Line

El Stitch prohíbe bordes de 1px para separar secciones — usa diferencia de tono de fondo. En /coleccion: el header tiene bg-card (blanco) sobre el bg-background (crema) del contenido. La separación es tonal, no una línea. Alineado con rules.md §9 — No-Line Rule.

Animaciones — Framer Motion v12

Se usa AnimatePresence mode="wait" en contenidoColeccion.tsx para animar el cambio de pestaña. Las variantes están anotadas con type Variants como exige rules.md §8 (Framer Motion v12 es estricto con los tipos).

Variantes declaradas

const variantesContenido: Variants = {
  oculto: { opacity: 0, y: 10 },
  visible: {
    opacity: 1,
    y: 0,
    transition: { duration: 0.22, ease: 'easeOut' }
  },
  salir: {
    opacity: 0,
    y: -6,
    transition: { duration: 0.15, ease: 'easeIn' }
  },
}

Uso en el componente

<AnimatePresence mode="wait">
  <motion.div
    key={pestana}           {/* key distinta → remonta → anima */}
    variants={variantesContenido}
    initial="oculto"
    animate="visible"
    exit="salir"
  >
    {/* grid o estado vacío */}
  </motion.div>
</AnimatePresence>

El key={pestana} fuerza a React a desmontar y remontar el motion.div cada vez que cambia la pestaña. Sin esa key, AnimatePresence no detectaría el cambio y no animaría la salida del contenido anterior.
