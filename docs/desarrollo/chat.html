Store Zustand — chatStore.ts

Interface

interface ChatStore {
  mensajes:       Mensaje[]     // Array de mensajes en orden cronológico
  cargando:       boolean       // true mientras IA "procesa" (mock 1.4s)
  enviarMensaje:  (texto) => void
  limpiarChat:    () => void
}

Tipo Mensaje

interface Mensaje {
  id:         string     // timestamp-u / timestamp-ia
  rol:        'usuario' | 'ia'
  contenido:  string
  timestamp:  Date
}

Flujo de enviarMensaje

1. Crea {id, rol:'usuario', contenido, timestamp: new Date()}
2. set: mensajes = [...prev, mensajeUsuario], cargando = true
3. setTimeout(1400ms):
   getMockRespuesta(texto) → string
4. Crea {id, rol:'ia', contenido: respuesta, timestamp}
5. set: mensajes = [...prev, respuestaIA], cargando = false

Flujos de usuario

Flujo 1 — Chip sugerido

1
Usuario ve EstadoVacioChat (mensajes vacíos) 3 chips: "¿Qué cocino hoy?" · "Receta con lo que tengo" · "Dieta sin gluten"
2
Click en chip → onChipClick(chip.texto) → useChatStore.enviarMensaje(texto) El chip.texto se usa como contenido del mensaje de usuario
3
Store añade BurbujaUsuario + activa cargando = true → aparece IndicadorPensando El scroll automático lleva la vista al final del chat
4
Tras 1.4s: store añade BurbujaIA con respuesta mock + cargando = false IndicadorPensando desaparece, scroll al final de nuevo

Flujo 2 — Mensaje libre

1
Usuario escribe en BarraInputChat, botón Send activa (brand) La textarea se expande automáticamente hasta max 4 líneas
2
Pulsa Send o Enter (sin Shift) → mismo flujo que chip Si el texto no está en RESPUESTAS_MOCK → se usa RESPUESTA_DEFAULT genérica
3
Textarea se vacía + altura reset a auto tras enviar

Flujo 3 — Copiar respuesta IA

1
Usuario hace click en "Copiar" en las acciones de una BurbujaIA
2
navigator.clipboard.writeText(contenido) → botón cambia a Check "Copiado" Vuelve a "Copiar" tras 2 segundos con setTimeout

Flujo 4 — Volver desde el chat

1
Usuario hace click en ← del HeaderChat → router.back() ContenidoChat (fixed inset-0) se desmonta, la ruta anterior vuelve a ser visible
2
Los mensajes del store persisten mientras la app esté abierta (sin persistencia a localStorage) Al volver al chat, el historial de la sesión sigue visible

Plan Fase 6 — Integración real con Gemini

chatService.ts Nuevo servicio en src/services/chatService.ts. Método enviarMensaje(texto, contexto) → POST /api/chat. El contexto incluye alérgenos del perfilStore y top-3 items del despensaStore para enriquecer el prompt.
useChatIA.ts Hook en features/chat/hooks/useChatIA.ts con TanStack Query mutation. Sustituye la llamada directa al store. El store solo almacena mensajes; la mutación HTTP llama a chatService.
BE: POST /api/chat Endpoint Express autenticado. Recibe {mensaje, contexto}. Construye prompt enriquecido con despensa + alérgenos. Llama a Google Gemini API (gemini-1.5-flash). Persiste en historial MongoDB.
BE: GET /api/chat/historial Devuelve las últimas N conversaciones del usuario. Permite restaurar el historial en el dropdown del header. chatStore usará cargarHistorial().
Streaming Gemini Opcionalmente usar streaming (streamGenerateContent) para mostrar la respuesta palabra a palabra, igual que ChatGPT/Claude. Requiere SSE o WebSocket en el frontend.
