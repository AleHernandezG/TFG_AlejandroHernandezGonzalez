Middlewares de autenticación

  • optionalAuth — GET endpoints públicos pero user-aware (liked/guardado se calculan si hay token)
  • requerirAuth — POST toggles (like, guardar) exigen token válido → 401 si no lo hay

backend/src/middlewares/autenticacion.ts — optionalAuth añadido

export function optionalAuth(req, _res, next): void {
  const authHeader = req.headers.authorization;
  if (authHeader?.startsWith("Bearer ")) {
    const token = authHeader.split(" ")[1];
    try { req.usuario = verificarToken(token); } catch { /* sigue sin usuario */ }
  }
  next();
}

Filtros del feed

  • q — texto libre, busca en titulo y descripcion con regex insensible a mayúsculas
  • dificultad — CSV ("Fácil,Media") → $in en MongoDB
  • alergenos — CSV de IDs → $nin (excluye recetas que tengan alguno de esos alérgenos)
  • pagina / limite — paginación; límite máximo 50 (clampado en controller)

Flujos de datos

Feed del Home — usuario sin sesión

feedHome renders → useRecetasFeed({}) → GET /api/recetas → optionalAuth (sin token) → liked=false, guardado=false en todas

Feed del Home — usuario con sesión

useSession() → token → GET /api/recetas + Bearer token → optionalAuth decodifica usuario → liked/guardado calculados por receta

Toggle like — optimistic update

  1. Usuario pulsa el corazón
  2. Estado local: setLiked(!liked), setLikes(±1) — UI instantánea
  3. Mutación: POST /api/recetas/:id/like con Bearer token
  4. Si éxito → invalidate queries (feed + detalle) para sincronizar con BE
  5. Si error → rollback: setLiked(prev), setLikes(prev)

Guardar receta — optimistic update (mismo patrón)

toggleGuardado() → setState optimistic → POST .../guardar → onError → rollback
