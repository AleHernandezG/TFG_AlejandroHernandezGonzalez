3. Layout y capas sticky

La pantalla tiene cuatro capas apiladas verticalmente, gestionadas por CSS position: sticky y position: fixed:

CapaComponentez-indexPosición
1ª HeaderHome z-40 sticky top-0
2ª BuscadorFiltros z-30 sticky top-[56px] (altura del header)
3ª FeedHome (lista de cards) natural flujo normal, scrollable

El LayoutPrincipal de (main)/layout.tsx ya añade pb-[calc(4.5rem+env(safe-area-inset-bottom))] al <main>, por lo que el contenido del feed nunca queda tapado por la barra inferior.

Glassmorphism: Tanto el header como el buscador usan bg-background/80 backdrop-blur-md. Esto permite que los colores cálidos de las imágenes del feed "sangren" visualmente a través del header mientras el usuario hace scroll, creando el efecto editorial del DESIGN.md.

Función de tiempo relativo

function tiempoRelativo(fechaISO: string): string {
  const diffMs  = Date.now() - new Date(fechaISO).getTime()
  const diffMin = Math.floor(diffMs / 60_000)
  if (diffMin < 60) return `Hace ${diffMin}m`
  const diffH = Math.floor(diffMin / 60)
  if (diffH < 24) return `Hace ${diffH}h`
  return `Hace ${Math.floor(diffH / 24)}d`
}

9. FeedHome

Fichero: features/recetas/components/feedHome.tsx

Client Component Gestiona el estado de filtros y búsqueda, y renderiza el feed.

Estado interno

EstadoTipoUso
filtroActivostringID del chip activo (default 'todas')
busquedastringQuery del input de búsqueda

Filtrado de posts

const postsFiltrados = POSTS_MOCK.filter((post) => {
  if (busqueda === '') return true
  const q = busqueda.toLowerCase()
  return (
    post.receta.titulo.toLowerCase().includes(q) ||
    post.receta.descripcion.toLowerCase().includes(q) ||
    post.autor.nombre.toLowerCase().includes(q)
  )
})

El filtro por categoría (Vegano, Keto…) está preparado en el estado pero no aplica lógica de exclusión sobre el mock actual, ya que los datos mock no tienen campo de categoría. En Fase 5, la query al backend enviará el filtro como parámetro y el servicio filtrará correctamente. Añadir el campo categoria a DatosReceta completará el ciclo sin tocar la UI.

Animación staggered

{postsFiltrados.map((post, i) => (
  <motion.div
    key={post.id}
    initial={{ opacity: 0, y: 18 }}
    animate={{ opacity: 1, y: 0 }}
    transition={{ duration: 0.3, delay: i * 0.07, ease: 'easeOut' }}
  >
    <TarjetaPost post={post} />
  </motion.div>
))}

Cada card entra con un retraso incremental de 70ms, creando un efecto de cascada suave que evoca la sensación de un feed que se va "descubriendo".

PaginaHome es un Server Component puro. No contiene ningún hook, estado ni manejador de eventos. La interactividad está encapsulada en FeedHome (Client Component), respetando el patrón App Router de Next.js 14: empujar el límite 'use client' lo más abajo posible en el árbol.

13. Preparación para Fase 5 (backend)

La arquitectura actual permite conectar el backend sin tocar los componentes. El único cambio necesario será añadir una capa de servicio y un hook:

// Fase 5 — añadir sin tocar los componentes existentes

// 1. src/features/recetas/hooks/useRecetasFeed.ts
export function useRecetasFeed(filtro: string) {
  return useQuery({
    queryKey: ['feed', filtro],
    queryFn:  () => recetasService.obtenerFeed(filtro),
  })
}

// 2. src/features/recetas/services/recetasService.ts
export const recetasService = {
  obtenerFeed: (filtro: string) =>
    apiClient.get<PostFeed[]>(`/recetas/feed?filtro=${filtro}`),
}

// 3. feedHome.tsx — sustituir POSTS_MOCK por el hook
const { data: posts = [] } = useRecetasFeed(filtroActivo)

TarjetaPost, HeaderHome y BuscadorFiltros no se modifican en Fase 5.
